Technical Implementation Details

Backend Integration Requirements

This section outlines the technical requirements and specifications that the backend team needs to implement to support the frontend routing structure.

Dynamic Route Parameters

Parameter Type Description Example
:universityId String/UUID University identifier for academic resources univ-123-abc
:articleId String/UUID Article identifier for entertainment content article-456-def
:newsId String/UUID News article identifier news-789-ghi
:topicId String/UUID Discussion topic identifier topic-012-jkl

Query Parameter Specifications

Parameter Type Description Example Values
category String Store category filtering electronics, books, clothing
search String Search query for store items laptop, textbook, shirt
page Integer Pagination page number 1, 2, 3, ...
limit Integer Items per page (optional) 10, 20, 50

Authentication & Authorization

Authentication Flow Requirements:

  • Modal-Based Authentication: Login and registration are handled through modal interfaces, not separate pages
  • Google OAuth Integration: Requires proper callback URL handling and token exchange
  • JWT Token Management: Automatic token refresh mechanism implemented on frontend
  • Session Persistence: User sessions maintained across browser refreshes

Protected Route Handling:

  • Frontend implements route guards for protected content
  • Unauthorized access redirects to login modal
  • Token validation occurs on each protected route access

Content Management Features

Interactive Content Support:

  • Entertainment Content: All articles, news, and events support comments, likes, and bookmarks
  • Real-time Interactions: Like and bookmark counts update dynamically
  • Comment System: Nested comments with user attribution
  • Content Filtering: Category-based and search-based filtering

Store Management:

  • Product Catalog: Supports pagination and category filtering
  • Search Functionality: Full-text search across product names and descriptions
  • Inventory Management: Stock levels and availability tracking

⚠️ Implementation Notes

Routing Architecture: The frontend uses React Router DOM v7 with a centralized routing configuration in PublicRoutes.tsx. This structure supports the current implementation and provides flexibility for future feature expansion.

API Compatibility: All routes are designed to work with RESTful API endpoints and follow standard HTTP conventions.
